## Import and redaction

An export is a folder:

```
<export>/export.json                 { "name": "Sample wiki export", "spaces": { "Enterprise Space": { "description": "…" } } }
<export>/<Space name>/**/*.md        the pages (other file types are copied as they are; only text is redacted)
```

`importer.importExport({ folder, by })`:

1. For each space folder: find the space by name, or create it with the space manager (local filing under
   `<appBaseDir>/spaces/<slug>/files`), then initialise its filing.
2. For each file: read it, `redact()` it if it is text, write it through the filing wrapper, and tell the search
   indexer (`updateFileInSpace`). The unredacted text only ever exists in memory.
3. Write the source record: `{ id (slug of the name), name, kind: 'folder', from, state: 'Imported' | 'Failed: …',
   lastRunAt, by, spaces: [{ name, documents }], documents, redacted: { email, phone, id } }`.

A second import of the same export has the same id, so it replaces the record and overwrites the files.

`redact()` is three patterns, applied in this order so an ID number is not half-eaten as a phone number:
13-digit South African ID numbers, email addresses, and phone numbers (`+27…`, `0xx xxx xxxx`, international
`+` forms of 9 to 15 digits). Text inside fenced code blocks is redacted too. It does not touch names.

`seed()` (called by NooblyJS's seed) imports `sample-export/` once: it does nothing when the source record exists.

## Asking

`POST …/ai/chat/search` today: no AI agent → 400. Now:

- **No agent:** `answers.passageAnswer(question, hits)` takes the top three visible search hits, picks from each
  the sentences that share the most words with the question (up to two, 320 characters), and answers
  `"<passage> [1] <passage> [2] …"`, opening with "No model is configured here, so this is what the sources
  say, not a written answer." The response has the same shape as a model's (`response`, `sources`,
  `searchQuery`), plus `model: null`.
- **Either way** the answer is kept in `answers.json` (newest 500) with an id, and the response carries `answerId`.

Visibility is unchanged: hits pass through the same space filter the summariser uses before anything is read.

## Answer actions

| Route (under `/wiki/api/v1`, standalone `/applications/wiki/api`) | Who | What |
| --- | --- | --- |
| `POST knowledge/answers/:id/link { itemId }` | `draft` | Each source becomes a link `{ id, title, kind, source }` on the spec, through `host.service('product').linkKnowledge(itemId, links, actor)`. 409 when the Product Factory is not running |
| `POST knowledge/answers/:id/save { spaceName, title }` | someone who can write to that space | Writes `Answers/<title>.md` (question, answer, a Sources list) and indexes it |
| `POST knowledge/answers/:id/wrong { reason }` | `draft` | Records the report on the answer; adds a flag per cited document; emits `knowledge.answer_flagged { answerId, sourceIds, reason }` |
| `GET knowledge/needs-review` | signed in | The open flags, newest first |
| `POST knowledge/needs-review/resolve { id }` | `approve` | Marks the flag reviewed (who, when) |
| `GET knowledge/sources` · `POST knowledge/import { folder? }` | signed in · Owner (`admin` standalone) | The sources; run an import (no folder: the bundled sample) |
| `GET knowledge/process-model?spaceName=&path=` | someone who can open the page | The model around that page |

A knowledge id is `"<Space name>/<path>"` made safe for the Product Factory's id rule (a slug), kept with the
real space and path so links still open the page. `access.js` refuses an agent on every write, and each write is
recorded with `host.audit.record()` when hosted.

## Process model

A model page carries one block:

    ```process-model
    level: L1
    code: [PLACEHOLDER VC-03]
    name: Supply
    band: Value chain
    parent: L0 Enterprise Process Model.md
    order: 3
    linked-items: PRD-031, ADR-014
    ```

`processModel.modelFor(space pages, path)` returns `{ page, parents, children, bands }`: for an L0 page `bands` is
`[{ name, processes: [{ code, name, path, children }] }]` in the order Enterprise, Value chain, Support; for any
page, its children (pages whose `parent` is this page) and its chain of parents. `linkedItems` are resolved by
the route through `host.service('product')?.artefactsFor(id)` and `host.service('workflows')?.item({ id })` to a
title and a link; an id NooblyJS does not know is shown as text.

In the browser `processModelController.hydrate()` runs where the other blocks are hydrated. It replaces the
block's code element with: a breadcrumb of parents, the bands (each chevron a link to its page), the children,
and "Used across NooblyJS". The URL is the page's own wiki URL, so deep links and refresh work as for any page.
Built with `createElement` and `textContent` only.

## Knowledge for agents

`register()` returns `provides: ['knowledge']` and `services`:

- `contextFor({ itemId, query, limit = 3 })` → `[{ id, title, kind, space, path, href, passage }]`. With no
  `query` it asks the Product Factory for the item's title. Uses the same search and the same visibility filter,
  with the spaces a signed-out reader could see (team and public), because an agent has no session.
- `search(query, { limit })`, `flagged()` (open flags), `status()` (spaces, sources, open flags).

NooblyJS registers an app's services under its name and under each name in `provides`.

In the Product Factory, a draft already receives `contextFor()`'s result as context. Now the draft record also
keeps those documents as `sources`, the draft's text ends with "Sources: [1] <title> …" when it has any, and
applying the draft adds them to the spec's Linked knowledge.

## Screens

- **Sources** and **Needs review** are datasources screens (the pattern of `screens/agents.js`), with rows in
  the sidebar under Content. Needs review's count is the nav badge, from `status()`.
- The wiki's AI panel shows **Add to item**, **Save as page** and **This is wrong** under a search answer.
- All three are written in the standalone sources and ported; nothing in `public/app` is edited by hand.
