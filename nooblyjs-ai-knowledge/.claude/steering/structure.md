# Knowledge Repository: where things live as a NooblyJS hosted app

> **As built (2026-10-09), which differs from the plan below.** The app mounts at **`/wiki`** with the name `wiki`,
> not `/knowledge`. `backend/` and `applications/` were merged into **`src/`**, so `src/` is the CommonJS Wiki
> Platform (`src/datasources`, `src/wiki`, `src/shared`, `src/web`), not hosted-only ESM. The hosted code is the
> root `index.mjs` plus `src/hosted/` (the adapter that runs the legacy modules under the host), `public/js/module.js`, `public/js/pages/`, `public/js/hosted/`, the UI generated by `scripts/port-wiki-ui.mjs` (`public/app`, `public/vendor`, `public/css/wiki-app.css`)
> and `test/*.test.mjs`. `CLAUDE.md` ("Hosted in NooblyJS") lists what is hosted so far. The legacy datasources
> screens (workflows, schedules, runs, repositories, spaces, agents, prompts, users, settings) are hosted the same
> way at `/wiki/datasources/…` (`public/js/pages/datasources.js`, open to everyone signed in), and the workflow definitions they
> manage are in this repo's `workflows/` folder. §1–§5 below are still the
> target for screens, data and services `[CONFIRM against the /wiki decision]`.

> `tech.md` has the platform rules, the `register()` contract and the migration from the legacy
> Wiki Platform. This file covers the layout of the **hosted** Knowledge app at **`/knowledge`**.
> For what the screens show, see `../nooblyjs-ai-host/.claude/steering/product.md` §5.6 and the mockups in
> `../nooblyjs-ai-host/.claude/steering/brief/`. The legacy app's layout is described in `CLAUDE.md` and `.docs/`.

## 1. Layout

```
nooblyjs-ai-knowledge/
  index.mjs                 register(app, serverManager, options) → HostedApp (ESM)
  server.mjs                standalone nooblyjs-mode dev server (`npm run start:noobly`); app.js stays the legacy entry
  package.json              "main"/"exports" → ./index.mjs; legacy scripts unchanged
  src/                      hosted code only (ESM: src/package.json has { "type": "module" })
    routes/                 one file per area under /knowledge/api/v1: ask.js · spaces.js · collections.js ·
                            documents.js · sources.js · process-models.js · graph.js · review.js ·
                            contributions.js · access.js
    services/               search.js · answers.js (cited) · ingest.js (PII redaction first) · freshness.js ·
                            review.js · process-models.js · backlinks.js
    repos/                  spaces · collections · documents · sources · process-models · review (over host.store)
    workers/                connectors (wiki export, GitHub, Confluence, Jira, Zendesk, Drive/SharePoint, NooblyJS) · indexer
    seed/                   Enterprise space, the L0 model, sample documents for the PRD-031 story
    util/
  public/                   hosted UI files (the legacy public/*.html are never served by the hosted app)
    css/knowledge.css       every selector starts with [data-module="knowledge"]
    js/
      module.js             route table (§2)
      pages/                ask.js · spaces.js · process-model.js · collections.js · sources.js · graph.js ·
                            review.js · contributions.js · access.js
  scripts/import-application.mjs   one-off: .application/ JSON → data/knowledge/ Markdown + YAML
  test/                     node:test for the hosted code (its own package.json { "type": "module" }; legacy Jest stays in tests/):
                            register.test.js · module.test.js · fixtures/host.js · …
  app.js · src/{datasources,wiki,shared,web} · tests/ · .application/   legacy Wiki Platform (until retired)
```

## 3. Data (`data/knowledge/`, written only by the NooblyJS process)

```
data/knowledge/
  spaces/<space>/<collection>/<doc-id>.md     a document: front matter (source, path, owner, lastReviewedAt,
                                              citedBy, piiRedacted: true) + body
  process-models/<space>/L0.md                the L0 model (bands, chevrons, codes)
  process-models/<space>/L1/<code>.md · L2/<code>.md
  sources/<source-id>.yaml                    connector config (secrets by reference only) and sync state
  review/<doc-id>.md                          why a document needs review, and its decision
  flags/<flag-id>.md                          "This is wrong" reports
  .index/                                     search and embedding sidecars (rebuildable, never the source of truth)
```

## 4. Talking to the rest of NooblyJS

Knowledge is the **context provider for every agent**, so its `services` matter most:

| `services` | Used by |
| --- | --- |
| `search(query, { space, collection, limit })` | Home search, Product Factory side panels |
| `answer(question, { itemId })` → `{ text, citations }` | Ask & search; teammates in chat and Teams |
| `find(query, { limit })` → `{ files, folders }` (NooblyJS 2026-10-10) | NooblyJS Product Factory · Architecture · Knowledge: files from the wiki's search, folders whose path holds every word, each with its space, path and link |
| `locate({ kind, space, path })` → the file or folder, or null | Architecture · Knowledge, before linking one |
| `contextOf(links, { maxChars })` → each link's text (a file) or its documents and first texts (a folder) | the Software Factory's intake: the knowledge an architect linked goes into each work item |
| `contextFor({ itemId, text, limit })` → passages with citations | `nooblyjs-ai-product` drafting agents, teammate tasks, factory stations. Drafts must cite what they used |
| `backlinks(target)` | the "Used across NooblyJS" panel |

| Direction | What |
| --- | --- |
| Emits | `knowledge.document_ingested`, `knowledge.answer_flagged`, `knowledge.review_flagged`, `knowledge.source_synced`, `knowledge.space_pinned`, `agent.action` |
| Listens to | `spec.updated` and `adr.accepted` (NooblyJS itself as a live source), `pr.merged` (finding documents that contradict merged code) |
| Browser calls | Knowledge pages call `/knowledge/api/v1`. **Add to PRD-031** calls `/product/api/v1/specs/PRD-031/knowledge` |

## 5. Seed

`seed({ reset })` writes the Enterprise space with the L0 model (Value chain: Plan PL, Procure PR,
Supply SU, Sell SE, plus Enterprise and Support bands, with `[HC]`, `[FR]`, `[IS]`, `EM` as
placeholders until the real codes arrive), and the documents the PRD-031 story cites
(e.g. `kn-slot-capacity-model`, ADR-013).
